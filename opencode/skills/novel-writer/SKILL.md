# Novel Writer Skill

Turns `novel.spec.yml` into a complete multi-chapter novel, one chapter per file.

## Inputs: novel.spec.yml

| Key | Meaning |
|---|---|
| `wordsPerPage` | Words in one page |
| `pagesPerChapter` | Pages in one chapter |
| `PlotConfig.plotAgentEnabled` | If true, missing chapters/points are generated by the `plot-agent` |
| `PlotConfig.theme` | Core theme of the novel |
| `PlotConfig.numberOfChapters` | Total chapters |
| `PlotConfig.pointsPerChapter` | Plot beats per chapter |
| `PlotConfig.sexualContentLevel` | Intimacy level for scenes (see Content rules) |
| `PlotConfig.emotionalLevel` | Emotional intensity and tone |
| `PlotConfig.sceneVariety` | Arc, motifs, settings, costume/wardrobe themes to rotate |
| `Characters[]` | name + relationship |
| `Backstory` | Premise and dynamics between characters |
| `Chapters[]` | `Chapter` number and `Points[]` already written by the user |

## Derived numbers

- `wordsPerChapter = wordsPerPage * pagesPerChapter`
- `wordsPerPoint = wordsPerChapter / pointsPerChapter` (use as a target, ±20%)
- Example: 1000 x 6 = 6000 words per chapter; 15 points -> ~400 words per point.

## Workflow

1. **Load and validate** the spec. Fix obvious typos silently (e.g. "Boyfrind"). Report missing required keys and stop.
2. **Create the story bible** at `novel/bible.md`: character sheets (voice, desires, flaws, speech habits), timeline, settings, wardrobe/motif tracker, running-threads list. Keep it updated after each chapter.
3. **Plan** (if `plotAgentEnabled: true`): delegate to the `plot-agent` subagent via the Task tool to write `novel/outline.yml` with `numberOfChapters` chapters and exactly `pointsPerChapter` points each. User-supplied points are kept verbatim; the agent only fills gaps and pads partially-filled chapters.
4. **Write**: for each chapter N in order, delegate to the `chapter-writer` subagent via the Task tool with chapter N. Output goes to `novel/chapter-NN.md`. Never write chapter N+1 before N is saved. Local models have a small per-response output limit (e.g. 4096 tokens), so a chapter is written in parts of 3 points each into `novel/.parts/chapter-NN-pK.md`, then assembled with `cat`. Plan outlines the same way (a few chapters per write).
5. **Check** each chapter before moving on:
   - Word count within ±10% of `wordsPerChapter`
   - All points covered, in order
   - Continuity with `bible.md` and previous chapter's ending
   - Ends with a hook or emotional beat leading into the next chapter
   If a check fails, rewrite or extend the chapter once.
6. **Update** `bible.md` and `novel/progress.md` (chapters done, word counts, open threads).
7. **Assemble** (when asked): concatenate chapters into `novel/novel.md`.

## Output layout

```
novel.spec.yml
novel/
  bible.md
  outline.yml
  progress.md
  chapter-01.md ... chapter-NN.md
  novel.md            (optional, assembled)
```

## Writing craft rules

- Third person limited, past tense, unless the spec says otherwise.
- Each point becomes a scene or part of a scene with concrete setting, sensory detail, dialogue and interior thought; do not summarize points as bullet outcomes.
- Escalate gradually across chapters; do not spend the whole arc in the first chapters.
- Give secondary characters their own motives and agency, not just reactions.
- Use the `sceneVariety` list as a rotation: vary locations, occasions, outfits and power dynamics across chapters.
- Describe clothing and settings with culturally accurate detail (fabrics, drapes, jewelry, textures) as specified in the spec.
- Start every chapter file with `# Chapter N: <Title>`.

## Content rules

- All characters are adults (18+) and must be portrayed as such. Never write sexual content involving anyone under 18.
- Coercion, manipulation and humiliation in this genre are depicted as fiction about the characters' dynamics; keep the narrative focused on psychology, power and emotion. Do not include real people.
- Interpret `sexualContentLevel` as the *heat* of the prose: sensual, charged, and emotionally intense, with explicit moments handled through implication, tension, and aftermath rather than anatomical or step-by-step description. If the user wants a different register, they should adjust the spec and review output locally.

## Commands the user may give

- "plan the novel" -> steps 1-3
- "write chapter N" -> steps 4-6 for that chapter
- "write the novel" -> all steps
- "revise chapter N: <note>" -> rewrite using the note, re-run checks, update bible
